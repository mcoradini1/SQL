Example 1: Basic Database and Table Creation

create database register;      -- command 1

use register;                  -- command 2

create table people (          -- command 3
name varchar(30),
age tinyint(3),
sex char (1),
weight float,
height float,
nationality varchar(20),
); default charset = utf8;     -- note 1: add charset to accept latin characters.

Additional Notes:

register is the name of the database.
A database is composed of tables; tables store records; and each record consists of fields.
The semicolon (;) indicates the end of an SQL command.
This example represents a simple table definition intended for demonstration purposes.

Example 3: Using the database created on example 2, and adding more constraints and best practices. Using more
appropriate data type for each case.


use register;                  -- command 1

create table people (          -- command 2

id int not null auto_increment,
`name` varchar(30) NOT NULL,
`date_of_birth` date,
`sex` enum ('M', 'F'),                            -- note 4 Enum (Can only use M or F)
`weight` decimal(5,2),                            -- note 5 five spaces, and two after the comma (ex: 102,30)
`height` float(3,2),                              -- note 6  three spaces and two after the comma (ex: 1,99)
`nationality` varchar(20) default 'Brazil',
primary key (id)                                  -- note 8: Setting primary key
);

describe register;              -- command 3 (can also be desc register;)

show tables;                    -- command 4

Detailed Explanation of Changes and Constraints:

Constraints: It is important to note that constraints are written before or after the data type depending on the
constraint, they may be written in uppercase or lowercase, and they are not separated by commas. Instead, constraints
are separated by spaces within the column definition.

NOT NULL Constraints: Fields such as name and id marked as NOT NULL to guarantee that essential information is always
provided. The id will automatically receive value due to auto_increment.

AUTO_INCREMENT: automatically generates a new value for every inserted row, preventing duplication.

DEFAULT: Automatically assigns a predefined value to the inserted row.

Date of Birth Instead of Age: Storing date_of_birth allows the system to calculate age dynamically, ensuring
accuracy over time.

Primary Key (id) - Uniquely identifies each record in a table. It must contain unique values and cannot
be NULL, ensuring that every row can be reliably referenced.

Additional Note:

Backticks (`) are used in this example only to demonstrate that SQL allows identifiers (such as database or table names)
to be enclosed in them. Their usage is optional in this context and not required unless dealing with reserved words or
special characters.

Example 4: Adding information to the table people, using 5 different ways of Insert into.


insert into people                                              -- command 1 (first way)
(id, name, birthday, sex, weight, height, nationality)
values
('1' 'Marlon' '1995-08-13' 'M' '90.12' ,'1.95', 'Italy');


insert into people                                              -- command 2 (second way)
(name, birthday, sex, weight, height, nationality)
values
('Susan' '1996-05-28' 'F' '50.12' ,'1.64', 'Portugal');


insert into people                                              -- command 3 (third way)
(id, name, birthday, sex, weight, height, nationality)
values
(DEFAULT, 'Marine' '1999-01-28' 'F' '60.25' ,'1.70', 'Italy');


insert into people                                              -- command 4 (fourth way)
values
(DEFAULT, 'Allan' '1990-01-17' 'M' '85' ,'1.80', 'Mongolia');


insert into people                                              -- command 5 (fifth way)
values
(DEFAULT, 'Mario' '1989-01-21' 'M' '72' ,'1.87', 'Portugal'),
(default, 'Marianne' '1975-01-22' 'F' '58.11' ,'1.70', 'Italy'),
(DEFAULT, 'Adrian' '1995-01-21' 'M' '50.12' ,'1.90', 'Italy');

select * from people;                                            -- command 6 (select/show everyone in people)

Detailed Explanation:

1 - Inserting a record by explicitly specifying all columns, including the id.
2 - Inserting a record while omitting the id column, allowing the database to assign it automatically.
3 - Using the DEFAULT keyword to let the database generate the default value for the id.
4 - Inserting values without listing column names, assuming the values are provided in the exact order
defined in the table schema.
5 - Inserting multiple records in a single INSERT statement, which is more efficient than inserting rows one by one.

Example 5: Adding Columns Using FIRST, AFTER, and Default Position
In this example, different ways of adding a new column to the people table are demonstrated.
Depending on the syntax used, a column can be added at the end of the table, after a specific column,
or as the first column.

alter table people                                              -- command 1 (add to the end)
add column profession varchar(10);

alter table people                                              -- command 2 (delete column)
drop column profession;

alter table people                                              -- command 3 (add it after name)
add column profession varchar(10) after name;

alter table people                                              -- command 4 (add it in first)

Example 6: In this example, the MODIFY clause is used to change the data type and constraints of an existing column
in the people table. Because the table already contains data, adding or modifying constraints can lead to errors
if existing rows do not comply with the new rules.

alter table people                                              -- command 1
modify column profession varchar(20) not null;                  -- Wrong
modify column profession varchar(20) not null default '';       -- Correct way to do

Detailed Explanation:

MODIFY allows changing a column’s data type, size, and constraints.
Adding a NOT NULL constraint on a column that already exists may cause an error if any row contains NULL values.
Since the column was added after the table already had data, existing rows may contain NULL in the profession column.

Defining a DEFAULT value ensures that:
existing NULL values can be replaced,
future inserts do not violate the NOT NULL constraint.
Using a default empty string ('') is a common workaround when a meaningful default value is not available.
As in the previous example, column position does not need to be specified when modifying a column.

Example 7: Renaming Columns and Tables Using CHANGE and RENAME

alter table people                                                 -- command 1
change column profession prof varchar(20);                         -- Wrong
change column profession prof varchar(20)not null default = '';    -- Rewrote Correctly

alter table people                                                 -- command 2
rename to people_all;

Detailed Explanation:

When using CHANGE, all column definitions must be rewritten. If it constraints such as NOT NULL or DEFAULT are not
explicitly specified, they are lost. In a table that already contains data, renaming a column without redefining
constraints may cause issues as example 6 advise.

Renaming a table with RENAME TO changes the table name but does not affect its structure or data.

Example 8: More Constraints (if not exists, if exists, unique, unsigned)
------------------------------------------------------------------------------------------------------------------------

create table if not exists courses (                                -- command 1
name varchar(30) not null unique,                                   -- note 1
description text,
time_courses int unsigned,                                          -- note 2
total_classes int unsigned,
release_year year default '2024',
) default charset = uf8;

alter table courses                                                 -- command 2
add column course_id int first;

alter table courses                                                 -- command 3
add primary key (course_id);

describe courses;                                                   -- command 4

Notes:

Note 1: Constraint unique is different from primary key... It won't allow another equal name.
Note 2: Unsigned is to don't consider +/- signals (economy of 1 byte per data)
